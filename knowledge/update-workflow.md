# 更新同步流程

## 原版游戏更新

1. 在隔离目录下载新专服 Build。
2. 记录 App Build ID、Depot Manifest、JAR SHA-256 和明文源码树哈希。
3. 创建新的不可变游戏快照，完整保留旧快照。
4. 比较 Lua、scripts、文本元数据、Java class 和字节码 API。
5. 标记删除、改名、签名变化及事件/网络协议变化。
6. 重建 JSONL 与 SQLite FTS5 索引。
7. 运行覆盖率、结构和实际查询验证。
8. 全部通过后更新 `current.json`，再由各 Mod 项目独立完成兼容性审查。

## 发布阻断条件

- JAR 或明文源码哈希无法确定。
- CFR 失败或反编译覆盖率异常下降。
- `javap` 无法读取游戏自有类。
- 索引 JSONL 损坏或 SQLite FTS 查询失败。
- 当前知识库 Build 与目标服务器 Build 不一致。

公共知识库不接收任何 Mod 的源码、标识、依赖索引或发布记录。使用方只能从自己的项目单向读取原版证据。
